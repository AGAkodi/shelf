# Phase 5 completion report

4 November 2026. Scope: Phase 5 only. Email OTP plus verified wallet is the approved authentication decision. User subsequently confirmed successful email sign-in, Polygon switching and verified wallet ownership inside Nimiq Pay on Android.

1. **What was implemented:** dedicated Nimiq provider discovery, explicit permissions, account/network state, Polygon switching, rejection and disconnect handling; real email OTP sign-in; server-issued EIP-712 wallet challenges and verified wallet associations bound to the authenticated user and session. No payment transfer or loan activation was added.
2. **Files created:** `src/lib/nimiq/*`; `src/features/auth/EmailSignIn.tsx`; `src/features/wallet/*`; `shared/wallet-challenge.ts`; `supabase/functions/wallet-auth/*`; `supabase/functions/_shared/origins.ts`; migration `20261103000200_wallet_verification.sql`; `supabase/templates/otp.html`; wallet development/browser scripts and OTP test helpers; wallet browser configuration; provider, origin, database and browser tests; authentication decision document.
3. **Files changed:** application layout, development account UI, package manifests, Supabase configuration/function lockfile, shelf-api origin configuration, TypeScript/ESLint configuration, borrowing and catalogue regression tests, catalogue journey timeout, README, AGENTS, PROJECT_SPEC, IMPLEMENTATION_PLAN, DATABASE_SCHEMA, NIMIQ_INTEGRATION and TEST_PLAN.
4. **Database changes:** private challenges, verified wallets and session proofs; restricted service-only RPCs; live Auth session validation, unique wallet ownership, nonce expiry/atomic consumption, attempt/issuance limits and invalidation. Migration applied locally. Canonical identity remains auth.users.id. Built-in Web3 remains disabled. No financial table or loan authorization changes.
5. **Tests performed:** 91 pgTAP checks and 12 database/Auth/Storage scenarios passed. Ten wallet API scenarios passed, including real local email delivery/code replay, wrong signer/user/session/origin/secret, changed signed terms, concurrent redemption, expiry, metadata spoofing, rate limiting and password-only rejection. Nine borrowing API scenarios passed. Two wallet and two borrowing desktop/mobile journeys passed using real local Auth/Edge services; only wallet signing uses a test-only EOA provider. Final reruns passed: 36 unit tests, 10 catalogue browser tests and 30 route/provider browser tests. Mobile screenshot inspected; account details wrap without horizontal overflow.
6. **Build/type-check results:** lint, frontend TypeScript, Deno function checks, all 36 unit tests and production build passed with the account-state/origin hardening. Secret-pattern scan found no embedded JWTs, secret-key literals or private-key blocks in versioned/unignored source. Runtime environments, logs and test outputs remain ignored.
7. **Problems discovered:** reusable built-in Web3 authentication lacks demonstrated nonce consumption; wallet connection is not authentication; account changes can race signature/status responses; password sessions could otherwise bypass the selected OTP flow; local API origins omitted phone preview; new status elements made old test selectors ambiguous. A password test fixture invalidated a shared user's sessions. The long mobile catalogue journey exceeded its old 30-second total test budget during concurrent validation.
8. **Problems fixed:** approved OTP/session architecture; one-time server nonce and exact signed context; immutable verified associations; explicit OTP AMR requirement; account rechecks and stale-result guards; serialized invalidation/status handling; exact validated local origins shared by both functions; isolated password fixture; scoped loading selector. Catalogue total journey budget is 90 seconds, with individual assertion timeouts unchanged.
9. **Remaining limitations:** Device flow confirmed by the user on Android. Wallet version reported as latest from Play Store; exact version not supplied. Automated providers cannot establish native device behavior. Local email is captured in Mailpit, not delivered externally; hosted SMTP and HTTPS origins require deployment configuration. Contract-wallet verification is not implemented. Real USDT transfers and transaction verification belong to Phase 6. Development borrowing remains local-only and is disabled in the wallet preview.
10. **Acceptance criteria result:** PASSED. Automated checks passed and the user confirmed “verified ownership for this shelf session” after the requested device sign-in and Polygon flow. Exact wallet build remains unrecorded, a reproducibility limitation. Phase 6 is separately authorized.

## Device acceptance

Run `npm run dev:wallet`, open its LAN URL inside Nimiq Pay on the same Wi-Fi, request an email code, read the locally captured message at http://127.0.0.1:54324 on the computer, enter the code, connect, switch to Polygon and verify wallet ownership. Confirm the message “Wallet ownership verified for this Shelf session.” Record wallet version and OS, cancellation/retry and account-change behavior. This is a signature-only flow and moves no funds.
