# Phase 4 Completion Report

3 November 2026 — borrowing engine with a temporary local payment adapter. No Phase 5 work.

1. **What was implemented:** real local Supabase Auth sessions; server-created pending loans/payments from published books and enabled plans; explicitly labeled simulated payment; atomic/idempotent activation; real My Library, protected chapter reader, early return, expiry, reborrowing and transaction history. The responsive reader includes chapter selection and text sizing. Development UI is excluded from production builds. No money moves.

2. **Files created:** `supabase/migrations/20261103000100_borrowing_access.sql`; `supabase/development/adapter.sql`; `supabase/functions/shelf-api/index.ts`; shared server `handler.js`; function `deno.json`/`deno.lock`; `src/features/borrowing/{api,session,SessionProvider,DevelopmentAccount,DevelopmentCheckout}`; adapter install/serve and borrowing browser runner scripts; `playwright.borrowing.config.ts`; API and browser borrowing tests; this report.

3. **Files changed:** account provider wiring in main/AppLayout; BookDetails, Checkout, Library, Reader and Transactions pages; shared styles; local UI launcher; generated database types; Supabase configuration; package/lockfile (Deno development checker and scripts); ESLint and test TypeScript configuration; AGENTS, PROJECT_SPEC, IMPLEMENTATION_PLAN, DATABASE_SCHEMA, TEST_PLAN, README and .env.example.

4. **Database changes:** immutable payment environment defaults to production; production quote/receipt evidence constraints retained; development rows cannot fabricate chain evidence. Added service-only library/return/chapter authorization RPCs and current-clock expiry transition validation. Temporary checkout/complete/cancel SQL is outside migrations and only installed explicitly into the local Docker database. Existing RLS, immutable terms, unique live loan, idempotency and atomic paid-loan constraints remain. No new seed loans/payments or wallet associations. Clean reset/migration/storage seed succeeded.

5. **Tests performed:** 91 pgTAP assertions; 12 real Auth/database/Storage scenarios; 9 real Edge borrowing scenarios; 17 unit tests; 2 desktop/mobile borrowing journeys; 10 catalogue browser tests; 24 route/navigation browser tests. Parent Node test cases are excluded from scenario counts. Coverage includes concurrent checkout/completion, refresh recovery, server-derived quotes/identity, unpaid/missing/wrong-user/wrong-book access, actual private bytes, direct download/signing denial, return and repeated access denial, expiry before cleanup, reborrowing, cancellation, malformed IDs, disabled adapter and sign-out privacy. Expiry uses privileged test-only time shifting, never a deployed clock override. Secret-pattern scan and production-bundle development-control scan passed. Desktop/mobile reader screenshots were inspected: readable text, visible controls and no horizontal overflow.

6. **Build/type-check results:** ESLint, application/config/test TypeScript, Deno Edge entry-point checking and production build passed. Shared handler JavaScript is linted and tested through actual HTTP requests. Desktop/mobile journeys use Chrome emulation, not a Nimiq Pay device. No production payment evidence is claimed.

7. **Problems discovered:** expiry fixture trigger re-enabling encountered pending deferred events; browser test captured a URL before navigation completed; Deno inferred an empty origin list too narrowly; stale request errors could obscure loading; transaction-start time differed from current time in expiry transitions. Generated types contained whitespace. A verification run overlapped a formatting-triggered local Edge restart; it was rerun successfully after edits stopped. Runner emits a harmless NO_COLOR/FORCE_COLOR warning.

8. **Problems fixed:** flush deferred constraints before restoring fixture triggers; await reader URL before capture; explicit handler options typing; associate loading errors with current requests; validate expiry using current database time; normalize generated whitespace. Formatting applied to new engine/UI code. Production simulation controls and server credentials are absent from the frontend bundle.

9. **Remaining limitations:** adapter and local email/password panel are temporary, explicitly labeled and not production authentication/payment features. Real wallet auth requires the approved Phase 5 nonce/replay gate; USDT verification is Phase 6. Admin mutations/contributor submission remain later phases. Only original seeded demo chapters are available. Existing delivered text cannot be recalled; no DRM claim. Server rejects requests immediately after return/expiry; already open clients revalidate on focus/periodically and clear content at known expiry. No hosted deployment or real-device testing. Development adapter must be removed/disabled before final MVP acceptance.

10. **Acceptance criteria:** PASS for Phase 4 scope: real borrowing state machine, real loans/history, private authenticated reader, immediate server-side expiry/return denial, and explicitly local simulation. Required checks passed. Stop before Phase 5.
